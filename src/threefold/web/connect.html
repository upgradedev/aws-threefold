What the hook changes

The scenarios on the dashboard build their own payloads and then refuse them. That proves the gates run; it intercepts nobody. This hook is the difference: Claude Code calls it before every matched tool call, hands it the call it is about to make, and obeys the decision that comes back. A refusal here stops an edit at the moment of the edit, not in a pipeline twenty minutes later.

1 · Claude Code proposes a tool call

Write, Edit, Bash or Read, matched by the hook configuration.

2 · The hook asks this service

One POST /evaluate-tool-call, standard library only, no dependencies to install.

3 · The agent obeys the verdict

An approval runs. A refusal never executes, and the reason carries the model's sentence when one was produced.

Install, three steps

~2 minutes

Step 1 · Get the script

It ships in the repository at hooks/claude_code_hook.py. This page does not serve it: the Lambda package contains src/ only, so the hook is never uploaded and there is nothing here to download. Clone the repository and the file is already on disk. 

git clone <repository> threefold
cd threefold
echo '{"tool_name":"Read","tool_input":{"file_path":"README.md"}}' \
  | python hooks/claude_code_hook.py

The script takes no flags. It reads one JSON object on stdin and writes one decision on stdout, which is the whole of its interface, so the line above is both the smoke test and the thing Claude Code will do to it. Standard library only: there is nothing to install.

                THREEFOLD_INPUT_TOKENS
THREEFOLD_OUTPUT_TOKENS		
                0
                Projected token counts. Left at zero, the cost gate has nothing to weigh, which is why the loop and boundary gates are what stop things here.
              

              

                THREEFOLD_SESSION
                claude-code-local
                Used when Claude Code sends no session id. The session id is what the loop detector counts against.
              

            
          

        


        

          
It fails open, and says so

          

            If the service times out or the network drops, the hook returns allow with a reason that
            states the call was never checked. That is a deliberate trade: a guard that bricks the agent on a hiccup gets
            uninstalled by lunchtime. Where the risk is worth the interruption, set
            THREEFOLD_FAIL_CLOSED=1 and the same failure denies instead.
          

        

      


      

        
The contract, both directions


        

          
Claude Code writes this on stdin

          
{
  "session_id": "0f3c…",
  "tool_name": "Write",
  "tool_input": {
    "file_path": "src/threefold/domain/models.py",
    "content": "from boto3 import client"
  }
}

        


        

          
The hook writes this on stdout

          
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "Threefold refused this call. …"
  }
}

Verify without an agent

          

            

            
          

          

            Piping the JSON into the script gives the hook decision; sending it to the endpoint gives the verdict the hook
            translates. A refused call never enters the session's history, so repeating the boundary violation is refused for that
            reason every time and never reaches the loop gate. The third command is the one that halts a session.
