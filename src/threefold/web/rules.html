Architecture Rules

What each layer of your code may not depend on, enforced at the moment an agent writes the file

A rule names some files, what they may not import, and what they may import anyway.

When an agent asks to write a file a rule covers, Threefold reads the imports in the text it is about to write (for an edit, the new text, not the text being replaced) and refuses the write if one is forbidden. Imports are read from files ending …. A rule in observe mode never refuses: it records what it would have stopped, so you can introduce it to every team and read a week of the console before anyone is stopped.

Reading…

A project that has saved rules of its own is judged against them; every other project is judged against the shared set. Names are checked here against the stack's default pattern, Acme- and then 1 to 40 letters, digits or dashes, because a name outside it is recorded as unlabelled and would never match the calls you mean to govern.

Each rule

id — what a refusal quotes.

description — the sentence a developer reads when stopped.

mode — enforce (default) or observe.

when_path_matches — globs; ** crosses folders, * does not. Case is ignored.

forbid_imports — System.Data forbids it and everything under it, never System.DataAnnotations.

allow_imports — exceptions. The more specific pattern wins.
