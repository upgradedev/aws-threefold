The listing scans the session table and keeps the newest rows, which is honest at this scale and would not be at any other. A deployment with real traffic wants a secondary index on a recency key instead. The Calls column counts the retained history, which the store caps at the last 50 per session; cost and tokens are cumulative and are not capped.

Select a session on the left. The panel then reads GET /sessions/{id} ↗, which is a second request against the service rather than a re-display of the row.

A freeze is the operator kill switch, documented as POST /sessions/{id}/terminate ↗. It writes a terminal state that the service will not undo, and every later call in that session is refused. There is no unfreeze endpoint.
